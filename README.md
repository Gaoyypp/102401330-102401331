## 二、功能清单

### 核心功能（作业要求的完整闭环）

发布信息 → 浏览 / 搜索 → 查看详情 → 联系发布者 → 更新状态

1. **发布信息**：支持发布「寻物启事」和「失物招领」两类信息，物品名称、类别、地点、日期、描述、联系人、联系方式等字段，带完整的表单校验（空值、长度、日期、联系方式格式）。
2. **集中浏览**：首页信息墙以卡片形式展示全部信息，寻物 / 招领用不同配色区分，进行中信息优先、新发布在前。
3. **关键词搜索**：支持物品名称、地点、描述、联系人的模糊搜索，多个关键词用空格分隔（AND 语义），命中文字高亮显示。
4. **多维筛选**：按信息类型（寻物 / 招领）、物品类别（证件卡片 / 电子设备 / 书籍文具 / 钥匙 / 衣物配饰 / 其他）、状态（进行中 / 已结束）、地点筛选。
5. **查看详情**：详情页展示完整信息、物品照片、信息编号、发布时间与详细描述。
6. **联系发布者**：详情页提供联系方式，并支持**一键复制**（同时复制联系人、联系方式与信息编号，方便核对）。
7. **状态维护**：发布者可在物品找回 / 归还后将信息标记为「**已找到**」（寻物）或「**已归还**」（招领），也可重新开放；结束后的信息在列表中置灰沉底，详情页显示“请勿重复联系”提示，减少无效询问。
8. **我的发布**：依据浏览器本地标识识别本人发布，集中管理自己的信息与状态。

### 附加特点设计

| # | 特点 | 说明 |
| --- | --- | --- |
| 1 | **一键复制联系方式** | 详情页点击按钮即可复制“联系人 + 联系方式 + 物品 + 信息编号”，剪贴板 API 不可用时自动降级为 `execCommand` 方案 |
| 2 | **多维筛选与关键词高亮** | 类型 / 类别 / 状态 / 地点组合筛选，搜索结果中命中关键词以 `<mark>` 高亮 |
| 3 | **图片上传与本地压缩** | 发布时可选传一张物品照片，使用 Canvas 自动压缩到最长边 800px、JPEG 0.72 质量，避免 localStorage 超限 |
| 4 | **完善的表单校验与错误定位** | 字段级错误提示、标红、自动滚动到第一处错误；日期不能晚于今天；联系方式支持手机号 / QQ / 微信 / 邮箱及“微信：账号”写法 |
| 5 | **空状态与无结果提示** | 搜索无结果、我的发布为空、详情不存在均有友好引导 |
| 6 | **状态闭环与权限控制** | 只有发布者本人能修改状态；结束信息展示结束时间并沉底，支持误操作后重新开放 |
| 7 | **概览统计** | 首页实时统计信息总数、寻物、招领、已结束数量 |
| 8 | **相对时间展示** | “刚刚 / x 分钟前 / x 小时前 / x 天前” |
| 9 | **响应式布局** | 适配手机与 PC 浏览器宽度 |
| 10 | **XSS 防护** | 所有用户输入渲染前经 HTML 转义，搜索高亮在转义后进行 |

> 本项目**未实现**（作业明确不要求）：后台管理、实名认证、即时聊天、地图定位。

## 四、如何运行（测试人员指南）

### 方式一：直接打开（推荐，作业要求方式）

1. 下载（或 `git clone`）本项目的**全部文件**，保持目录结构不变；
2. 用 **Google Chrome 谷歌浏览器**直接双击打开根目录下的 `index.html`；
3. 首次打开会自动注入 6 条演示数据（其中 2 条属于“本机发布者”，便于体验“我的发布”和状态更新）；
4. 按页面导航即可体验完整流程。

> 不需要安装 Node、不需要启动服务器、不需要联网。

### 方式二：本地静态服务器（可选）

```bash
# 任选其一，在项目根目录执行
python -m http.server 8080
# 或
npx serve .
```

然后浏览器访问 `http://localhost:8080`。

### 推荐体验路径

1. 首页浏览卡片，切换「全部 / 寻物启事 / 失物招领」Tab，尝试关键词搜索（如 `校园卡`、`雨伞 食堂`）和类别 / 状态筛选；
2. 点击「发布信息」，直接点“确认发布”观察表单校验；填写完整后发布并上传一张图片；
3. 进入详情页，点击「一键复制联系方式」；
4. 打开「我的发布」，将一条寻物信息标记为「已找到」、一条招领信息标记为「已归还」；
5. 回到首页观察结束信息的样式与排序变化；搜索一个不存在的词查看空状态。

## 五、如何运行单元测试

本项目提供 **35 个**自动化测试用例（要求至少 10 个），采用白盒测试方法设计。

### 浏览器方式（Mocha + Chai）

- 用 Chrome 直接双击打开 **`test/tests.html`**，页面顶部显示绿色通过数与红色失败数；
- 测试框架文件已放在 `test/lib/` 本地目录，**离线可用**。

### 命令行方式（Node，可选，用于每日构建）

```bash
node test/node-runner.js
```

全部通过时退出码为 0，并输出：

```
测试结果：通过 35 个，失败 0 个，共 35 个
✅ 全部测试通过
```

### 测试覆盖的函数与场景

| 测试组 | 覆盖内容 |
| --- | --- |
| 编号与格式化 | `generateId` 前缀与唯一性、`formatDate` 正常与非法输入 |
| 安全与截断 | `escapeHtml` 五类危险字符、`truncate` 边界、`highlight` 转义后高亮 |
| 相对时间 | `timeAgo` 刚刚 / 分钟 / 小时 / 天 / 日期回退 / 未来时间 |
| 状态文案 | `statusLabel` 寻物“已找到”、招领“已归还”、进行中 |
| 联系方式校验 | `isValidContact` 手机 / QQ / 微信 / 邮箱 / 带标签写法、非法输入 |
| 发布校验 | `validatePost` 合法数据、缺必填、长度边界、未来日期、非法枚举 |
| 搜索筛选 | `matchKeyword` 多关键词 AND、`filterPosts` 类型 / 类别 / 状态 / 地点 / 组合 / 空结果 / 排序 |
| 统计 | `summarize` 各维度计数 |
| 数据层 | `add` 成功与拒绝、`getById`、`updateStatus` 本人 / 他人 / 非法状态 / 不存在编号、`getMine`、`canManage` |
| 演示数据 | `seedIfEmpty` 注入与不覆盖用户数据、样例类型完整性 |

**测试数据构造思路**：以一条“合法基线数据”为中心，用覆盖（override）方式派生边界与异常数据，覆盖空值、超长、未来日期、非法枚举、XSS 脚本、权限越权、数据不存在等“刁难”情况。

## 七、数据存储说明

- 所有数据保存在浏览器 `localStorage` 中，键名：
  - `campus_lost_found_posts_v1`：信息列表（JSON）；
  - `campus_lost_found_user_v1`：本机发布者标识（首次访问自动生成，用于识别“我的发布”）。
- 清除浏览器站点数据会删除全部记录；如需恢复演示数据，在浏览器控制台执行：
  ```js
  localStorage.removeItem('campus_lost_found_posts_v1'); location.reload();
  ```
- 纯前端方案没有真正的登录系统，“发布者”以当前浏览器标识为准，这是 localStorage 方案的固有边界；多设备同步需要后端支持，不在本次作业范围内。

## 八、技术栈

- 原生 HTML5 + CSS3 + JavaScript（ES5 兼容写法，无构建步骤）

- 图片处理：FileReader + Canvas（前端压缩）
- 单元测试：Mocha 10 + Chai 4（浏览器）/ Node assert（命令行运行器）
- 无任何第三方运行时框架依赖，测试框架已本地化
